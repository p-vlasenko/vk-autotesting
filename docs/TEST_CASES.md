### Auth
| ID | Тип | Сценарий | Ожидание |
|---|---|---|---|
| AU-1 | positive | POST /auth с кредами из `ApiConfig` | 200, JSON, `token` — непустая строка |

### Create (POST /booking)
| ID | Тип | Сценарий | Ожидание |
|---|---|---|---|
| CR-1 | positive | валидное бронирование | 200, JSON, `bookingid > 0`, `booking` равно отправленному; GET по ID возвращает те же данные |
| CR-2 | positive | без `additionalneeds` (необязательное поле) | 200, бронь создана |
| CR-3 | boundary | `totalprice = 0`; однодневная бронь `checkin == checkout` | 200, значения сохранены |
| CR-4 | boundary | длинные строки (300 символов), кириллица/спецсимволы/emoji | ограничение длины не документировано; фактически 200, строки сохранены без искажений |
| CR-5 | validation (param.) | отсутствует обязательное поле (`firstname`, `lastname`, `totalprice`, `depositpaid`, `bookingdates`) | текущее: 500 `Internal Server Error`, бронь не создана (поиск по оставшимся именам пуст). `@KnownBug`: 400 `Bad Request` и бронь не создана |
| CR-6a | validation | синтаксически невалидный JSON | 400 `Bad Request` (API ведёт себя корректно) |
| CR-6b | validation | пустой объект `{}` | текущее: 500 `Internal Server Error`. `@KnownBug`: 400 (побочный эффект не проверить: в теле нет имён для поиска) |
| CR-7a | validation | отрицательная `totalprice` | текущее: 200, бронь создана, GET подтверждает сохранение. `@KnownBug`: 400 и бронь не сохранена (поиск по именам пуст) |
| CR-7b | validation | `checkout` раньше `checkin` | текущее: 200, бронь создана, GET подтверждает сохранение. `@KnownBug`: 400 и бронь не сохранена |

### Read (GET)
| ID | Тип | Сценарий | Ожидание |
|---|---|---|---|
| GT-1 | positive + contract | GET /booking/{id} своей брони | 200, `application/json`, ответ соответствует `schemas/booking.json`, значения совпадают с отправленными (ожидание — исходный объект, а не ответ POST) |
| GT-2 | negative | создать свою бронь → удалить → GET по этому ID | 404, `text/plain`, тело `Not Found` |
| GT-3 | negative | нечисловой id (`abc`) | 404, `text/plain`, `Not Found` |
| GT-4 | positive | GET /booking — список | 200, корневой массив объектов `{bookingid: integer}` по `schemas/booking-list.json`, содержит ID своей брони |
| GT-5 | positive | фильтр `?firstname=&lastname=` с уникальными именами | 200, ровно один элемент — ID своей брони |
| GT-6 | negative | GET своей брони с `Accept: text/plain` | 418, `I'm a Teapot` (особенность API) |
| GT-7 | negative | фильтр `?firstname=` по несуществующему уникальному имени | 200, пустой массив |
| GT-8 | boundary (param.) | фильтр по имени + `checkin`/`checkout` = дата брони −1 / 0 / +1 день | по документации бронь найдена, если её дата ≥ даты фильтра. Текущее: `checkin` строго `>`, `checkout` работает как `≤` — 3 из 6 случаев расходятся с документацией (`[known bug]`); для них `@KnownBug` проверяет документированный результат |

### Update (PUT / PATCH)
| ID | Тип | Сценарий | Ожидание |
|---|---|---|---|
| UP-1 | positive (param.) | PUT с токеном в Cookie / с Basic auth | новая бронь отличается от исходной в каждом поле (гарантировано построением); 200, ответ равен новым данным; GET подтверждает |
| UP-2 | positive (param.) | PATCH `firstname` и `totalprice` с токеном / с Basic auth | 200, ответ и GET: изменены только эти поля, остальные прежние |
| UP-3 | negative (param.) | PUT / PATCH × без авторизации / с невалидным токеном | 403 `Forbidden` (особенность API); GET: данные не изменились |

### Delete
| ID | Тип | Сценарий | Ожидание |
|---|---|---|---|
| DL-1 | positive (param.) | DELETE своей брони с токеном / с Basic auth → GET | 201 `Created`, затем 404 `Not Found` |
| DL-2 | negative (param.) | DELETE своей брони без авторизации / с невалидным токеном | 403 `Forbidden`; GET: бронь существует |

| DL-4 | negative | DELETE несуществующей (своей, уже удалённой) брони с токеном | текущее: 405 `Method Not Allowed`. `@KnownBug`: 404 |

## Известные дефекты API
| Дефект | Тест |
|---|---|
| Нет обязательного поля / `{}` → 500 вместо 400 | CR-5, CR-6b |
| Отрицательная `totalprice` принимается | CR-7a |
| `checkout` раньше `checkin` принимается | CR-7b |
| DELETE несуществующего ресурса → 405 вместо 404 | DL-4 |
| Фильтр `checkin` не включает граничную дату (`>` вместо `≥`) | GT-8 |
| Фильтр `checkout` работает как `≤` вместо документированного `≥` (возможно, ошибка документации) | GT-8 |

Особенности (не дефекты, тестируются как есть): 200 + `Bad credentials` вместо 401; 403 вместо 401 без авторизации; 418 на `Accept: text/plain`.

Все дефекты подтверждены зелёными тестами `[known bug: текущее поведение]` основного набора; в `./gradlew knownBugs` ни один из 12 тестов не прошёл, то есть ни один дефект не исправлен. Риск GT-8: случаи со сдвигом 0 дней зависят от приведения дат на сервере (часовой пояс) и могут флакать после передеплоя стенда.
